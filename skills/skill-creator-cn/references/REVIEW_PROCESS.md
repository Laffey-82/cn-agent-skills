# 新技能评审流程

从"想做一个技能"到合并进仓库,按下面的顺序走。每一步都有通过标准,卡住就回到上一步,不要带病入库。

## 流程总览

1. 需求收敛;
2. 规划结构;
3. 生成骨架;
4. 编写正文;
5. 机器自检;
6. 人工评审;
7. 实测触发;
8. 更新索引并提交。

## 各步通过标准

| 步骤 | 通过标准 |
|---|---|
| 需求收敛 | 说清场景、触发条件、输入输出、目标用户,确认没有重复造轮子 |
| 规划结构 | 技能名动词短语、小写连字符;SKILL.md 主干,复杂内容拆 references/ 或 scripts/ |
| 生成骨架 | `python skills/skill-creator-cn/scripts/skill_scaffold.py <name> --description "<描述>"` 成功生成 |
| 编写正文 | 章节齐全但有内容,步骤具体到能执行,示例有信息量,没有空话 |
| 机器自检 | `style_checker.py` 无"必须"级问题;`skills-ref validate` 通过;Python 脚本 `py_compile` 通过 |
| 人工评审 | 对照 [skill-style-guide 的 REVIEW_GUIDE](../skill-style-guide/references/REVIEW_GUIDE.md) 和仓库 [docs/CHECKLIST.md](../../docs/CHECKLIST.md) 逐项过,内容原创 |
| 实测触发 | 在至少一种 Agent 里用真实任务跑通:触发词能识别,步骤顺畅,产出符合预期 |
| 更新索引 | README 技能表、CHANGELOG 补条目,提交信息按 `<type>: <subject>` 规范 |

## 机器自检命令

在仓库根目录执行:

```bash
# 风格检查(只做标记,结论人工确认)
python skills/skill-style-guide/scripts/style_checker.py <name>

# 官方技能校验
skills-ref validate ./skills/<name>

# Python 脚本语法
python -m py_compile skills/<name>/scripts/*.py
```

三条全过才算自检通过。脚本只做标记或测量,不替人下结论。

## 人工评审重点

机器抓不到的,逐条看:

- description 是否覆盖"用户会怎么说",而不是"这个技能能做什么";
- 步骤是否具体到 Agent 照着能做,不依赖"认真分析"这类含糊指令;
- 规则是否配了示例,示例是否可运行(脚本示例要实测过);
- 内容是否原创,不搬运、不改写来源不明的资料;
- 是否写清了验证方式,让用户知道装完怎么确认生效;
- 不需要的章节是否删掉,不为凑章节留空壳。

## 常见卡点

- **description 写不具体**:用"用户会怎么触发"反向检查,写不出触发词说明还没想清场景;
- **章节凑数**:新增章节必须带来新信息,否则删;
- **脚本没实测**:写了脚本就必须跑通再入库,不能只写文档;
- **名字像名词**:改成动词短语,名字直接说"做什么";
- **想一次做一堆技能**:一次只做一个,做完过完流程再开下一个。

## 什么时候可以跳过步骤

- 纯文档修订(改错字、补说明):走机器自检 + 直接提交即可;
- 已有技能的脚本增强:必须实测新脚本,风格检查跑该技能目录。

流程不是流程本身,目的是让每个技能都能回答三个问题:什么时候用、怎么用、怎么验证。

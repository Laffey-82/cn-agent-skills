# 代码审查速查表

## 四维检查清单

### 正确性

- 边界:空、零、负数、超长、并发;
- 异常:是否吞异常、失败后状态是否一致;
- 类型:浮点比较、隐式转换、时区;
- 逻辑:分支覆盖是否完整,有没有"以为不会走到"的分支。

### 安全性

- 输入校验:注入、路径穿越、XSS、SSRF;
- 敏感信息:密钥、token 是否硬编码或进日志;
- 权限:服务端校验,不信任前端;
- 依赖:来源可信、无已知漏洞。

### 性能

- 循环内重复计算、N+1 查询;
- 缺索引、缺缓存;
- 大对象是否不必要地常驻内存。

### 可维护性

- 命名是否表意;
- 死代码、重复代码;
- 错误信息是否可懂;
- 是否符合项目既有约定。

## 严重级别

| 级别 | 含义 | 处理 |
|---|---|---|
| P0 阻断 | 会出事故或安全问题 | 必须修 |
| P1 严重 | 明显缺陷 | 建议合并前修 |
| P2 一般 | 可修可不修 | 不阻塞 |
| P3 建议 | 风格与改进 | 可选 |

## AI 生成代码重点查

- 用了不存在的 API、错误的环境变量名;
- import 了没声明的依赖;
- except 后没日志没处理;
- 宽松正则、过大权限、硬编码密钥;
- 复制粘贴的重复逻辑。

## 意见写法

```text
[P1] src/auth.py:42 密码以明文存储
证据:这里直接写入 password 字段
建议:改用 bcrypt 哈希后再存储
```

好意见三要素:位置 + 证据 + 建议。缺一个都不是好意见。

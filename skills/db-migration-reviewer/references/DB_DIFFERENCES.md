# 数据库差异对照

## PostgreSQL 与 MySQL 关键差异

| 操作 | PostgreSQL | MySQL |
|---|---|---|
| 大表加索引 | `CREATE INDEX CONCURRENTLY`(不能放在事务里) | `ALTER TABLE ... ADD INDEX ... ALGORITHM=INPLACE, LOCK=NONE` |
| 加带默认值的列 | 11+ 快速,老版本重写表 | 8.0 瞬时(元数据操作),老版本重写 |
| 加 NOT NULL 列 | 必须带默认值才快 | 8.0+ 带默认值瞬时 |
| 事务内 DDL | 支持 | 隐式提交,事务内 DDL 会打断事务 |
| 外键检查 | 默认开启 | 默认开启(表级别可关) |
| 唯一约束验证 | 可 `VALIDATE CONSTRAINT` 延迟校验 | 无延迟校验 |
| 长事务 | 影响 vacuum 和膨胀 | 影响 undo 空间和锁 |

## 通用安全红线

无论什么数据库:

1. 大表操作先评估锁,优先在线变更;
2. DDL 和 DML 分开,不混在同一个迁移;
3. 破坏性操作(删表、删列、清数据)必须有备份和回滚;
4. 生产只允许向前迁移,回滚用新的 forward migration;
5. 迁移在合入前,先在数据量接近生产的副本上验证。

## 锁与阻塞速查

| 场景 | 现象 | 处理 |
|---|---|---|
| 普通 CREATE INDEX(大表) | 阻塞写入 | 改 CONCURRENTLY / 在线变更 |
| ALTER 加 NOT NULL 无默认值 | 整表重写,长时间锁 | 拆两步:先加可空/默认,再收紧 |
| 长事务 | 其他写被阻塞 | 缩短事务,分批提交 |
| 锁等待超时 | 报 lock timeout | 查锁等待链,杀掉阻塞会话 |

## 评审必问的五个问题

1. 这个迁移在数据量多大的表上跑?
2. 会不会阻塞读写?
3. 挂了怎么回滚?
4. 数据回填和结构变更分开没有?
5. 在类生产环境验证过没有?

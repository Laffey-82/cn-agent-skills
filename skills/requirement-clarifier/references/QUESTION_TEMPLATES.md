# 澄清提问模板

## 按维度组织问题

### 目标

- 这个功能做完,解决谁的什么问题?
- 怎么算成功?有没有可量化的标准?

### 范围

- 哪些必须做?
- 哪些明确不做?(防止范围蔓延)

### 用户与场景

- 谁在用?什么场景下用?
- 使用频率多高?对速度有什么要求?

### 边界与异常

- 输入为空怎么办?
- 用户操作到一半中断怎么办?
- 数据不存在、重复、超限怎么办?

### 验收

- 验收时我会看到什么效果?
- 有没有已有的例子或竞品可以参考?

### 约束

- 技术栈有没有限定?
- 时间、预算、合规有什么限制?

## 最短提问组合

用户不耐烦时,只问这三个:

1. 要解决什么问题;
2. 必须做什么、不做什么;
3. 怎么做算完成。

然后输出初稿,把不确定的地方列进"待确认问题"。

## 复述模板

```text
我的理解是:你要为【用户】实现【功能】,目标是【结果】,
核心场景是【场景】,验收标准是【标准】,约束是【约束】。
对吗?
```

## 常见坑

| 坑 | 表现 | 对策 |
|---|---|---|
| 用户说方案不说目标 | "加个数据库" | 追问"解决什么问题" |
| 需求全是"要"没有边界 | "还要能导出" | 记录为范围项,确认优先级 |
| 验收标准缺失 | "做好就行" | 给一个可验证的例子让用户确认 |
| 替用户做决定 | 直接按自己理解开工 | 列出选项让用户选 |

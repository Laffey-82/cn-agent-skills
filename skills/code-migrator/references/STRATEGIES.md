# 迁移策略细节

## 四种策略怎么选

| 策略 | 适用 | 风险 | 注意 |
|---|---|---|---|
| 绞杀者模式 | 大系统整体迁移 | 低 | 新旧并存期要维护两套,别拖太久 |
| 抽象分支 | 换底层实现 | 低 | 抽象层要稳,接口别频繁变 |
| 并行运行 | 行为不确定的迁移 | 中 | 对比逻辑要可靠,别误判 |
| 试点先行 | 一切迁移 | 低 | 试点要选有代表性、风险可控的模块 |

## 绞杀者模式要点

1. 在旧系统外围加一层路由;
2. 新实现逐步接管功能;
3. 每个功能切换后有验证和回滚;
4. 全部切换后移除旧系统。

## 抽象分支要点

1. 先加抽象层,行为不变;
2. 新实现放在抽象层后面;
3. 对比验证后切换默认实现;
4. 移除旧实现。

## 并行运行要点

- 新旧同时接收流量(影子流量或真实流量双写);
- 对比结果,不一致要能定位;
- 确认一致后切换,保留回滚期。

## 风险控制清单

- 每批独立可上线;
- 每批有测试兜底;
- 行为对照清单逐项确认;
- 回滚方案明确并演练过;
- 迁移过程有监控(错误率、延迟)。

## 常见失败原因

- 推倒重写,历史行为丢失;
- 没有测试兜底,改了发现不了;
- 一次动太多(同时换框架又重构);
- 忽略老代码的"怪癖",上线后行为不一致;
- 没有回滚方案,出问题只能硬扛。

# 需求评审

## 何时使用

- 用户说"帮我评审一下这个需求文档""PRD 有问题吗";
- 评审会前,需要一份缺口清单当议程;
- 需求要转开发,先确认能不能直接开工;
- 文档很全但总觉得有漏洞,需要系统性过一遍。

## 使用步骤

### 第 1 步:通读并定位

- 通读全文,标注不清楚的段落;
- 确认文档类型(PRD、需求规格、一句话需求),评审标准不同;
- 记下疑问点,评审不是重写文档。

### 第 2 步:跑脚本标记

命令见下面的[辅助脚本](#辅助脚本)。脚本检查结构完整性:必需章节、空章节、验收标准是否含糊、范围是否写了"不做"、占位符。

### 第 3 步:逐项人工评审

除脚本外,重点问:

| 检查项 | 通过标准 |
|---|---|
| 目标 | 说清解决什么问题,成功可度量 |
| 范围 | 写了"必须做"和"不做",没有暗含需求 |
| 用户与场景 | 谁用、什么时候用、频率 |
| 验收标准 | 每条可测试,QA 不用追问就能写用例 |
| 边界与异常 | 空值、中断、重复、超限有处理 |
| 优先级 | 需求有 P0/P1/P2,冲突时知道先保谁 |
| 约束 | 时间、技术栈、合规限制写清 |

### 第 4 步:输出评审报告

```markdown
# 需求评审报告:<文档>

## 结论
可开工 / 需补充 / 不通过
## 必须补充(阻塞开工)
## 建议补充
## 疑问清单
```

每条问题给"位置 + 问题 + 影响 + 建议",拿不准的标注需和作者确认。

## 输入与输出

- 输入:需求文档或 PRD;
- 输出:带严重级别的缺口清单与评审报告。

## 示例

**评审报告节选:**

```markdown
## 必须补充
- 验收标准:功能范围里"支持搜索"没有验收标准,无法判定完成
- 边界:用户已登录时再次访问登录页,行为未定义
## 建议补充
- 优先级:需求清单没有分级,冲突时无法取舍
```

## 辅助脚本

[scripts/prd_checker.py](scripts/prd_checker.py) 检查需求文档的结构完整性:

```bash
python skills/requirements-reviewer/scripts/prd_checker.py <需求文档.md>
```

检查:必需章节是否齐全且非空、验收标准是否含糊、范围是否同时写了"做"和"不做"、有无占位符。脚本只做标记,结论需要人确认。

## 注意事项

- **评审不等于重写**:给缺口清单,不替作者重写文档;
- 验收标准是核心:测不出来 = 没写完;
- 边界问题一次问清,别留到开发时才发现;
- 评审结论按严重级别给,别把建议当必须。

## 不适用场景

- 需求还很模糊,需要的是澄清(用 requirement-clarifier);
- 已经进入开发,发现需求问题(回到澄清或按变更流程);
- 用户只要逐条问答,不要报告。

## 验证方式

1. 触发:"评审这个需求文档";
2. 跑脚本:prd_checker.py 输出与人工抽查一致;
3. 走查:每条"必须"都有处理结论或作者确认;
4. 确认:报告中的疑问清单在评审会上逐条过掉。

# 技能风格指南

仓库里的技能风格得统一,不然用户装完一个再装一个,体验是断的。

## 1. 目录与命名

- 每个技能一个目录:`skills/<技能名>/SKILL.md`;
- `name` 小写、用连字符、和目录名一致;
- 技能名用动词短语,直接说"做什么"(如 `requirement-clarifier`),别用名词堆(如 `requirements-doc`)。

## 2. Frontmatter

```yaml
name: skill-name
description: 做什么 + 何时触发(中文为主,可附英文关键词)
license: MIT
metadata:
  version: "1.0.0"
```

两点要求:

- `description` 1-1024 字符,同时写清"做什么"和"什么时候用";
- 描述得覆盖中文说法,比如"当需求模糊、缺少验收标准时"。

## 3. SKILL.md 正文结构

统一用这些章节(按需增减):

```markdown
## 何时使用
## 使用步骤
## 输入与输出
## 示例
## 注意事项
## 不适用场景
## 验证方式
```

要求:

- 正文 500 行以内,内容多了拆到 `references/`;
- 步骤要具体到 Agent 照着就能做,规则尽量配中文例子;
- 章节标题用中文,代码和命令保持原文;
- 必须写"验证方式":在哪个工具、用什么触发词、预期产出是什么。

## 4. 内容质量

- 假设 Agent 已有能力:只写能改变决策的信息,删掉通用建议和空话;
- 正文以能执行、有信息量为准,行数是上限不是目标;
- 细节、模板、长例子放 references,不堆在正文;
- 示例必须有信息量,不凑数。

## 5. 语言

- 正文以中文为主,术语保留原文(TDD、frontmatter 这类);
- 例子优先中文场景:中文提交信息、中文注释、中文文档;
- description 中文为主,带上英文关键词,方便搜索。

## 6. 不收什么

- 抄来的、改写的、来源不明的;
- 跟仓库定位没关系的;
- 只有一两句话的"假技能";
- 没有验证说明的。

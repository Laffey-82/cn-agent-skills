# 技能风格指南

本仓库所有技能必须遵循统一的风格约定,保证一致性。

## 1. 目录与命名

- 每个技能一个目录:`skills/<技能名>/SKILL.md`;
- `name` 必须小写、用连字符、与目录名完全一致;
- 技能名用"动词短语"表达动作(如 `requirement-clarifier`),不用名词堆砌(如 `requirements-doc`)。

## 2. Frontmatter

```yaml
name: skill-name
description: 做什么 + 何时触发(中文为主,可附英文关键词)
license: MIT
metadata:
  version: "1.0.0"
```

要求:

- `description` 1-1024 字符,必须同时包含"做什么"和"何时用";
- 描述要覆盖中文触发表达,如"当需求模糊、缺少验收标准时"。

## 3. SKILL.md 正文结构

统一使用以下章节(按需增减):

```markdown
## 何时使用
## 使用步骤
## 输入与输出
## 示例
## 注意事项
## 不适用场景
## 验证方式
```

要求:

- 正文控制在 500 行以内;超出部分拆到 `references/`;
- 步骤必须具体到 Agent 能直接执行,每条规则尽量配中文示例;
- 每章标题用中文,代码与命令保持原文;
- 提供"验证方式":在哪个工具、用什么触发词、预期产出是什么。

## 4. 语言

- 正文:中文为主,保留必要术语原文(如 TDD、frontmatter);
- 示例:优先中文场景(中文提交信息、中文注释、中文文档);
- description:中文为主 + 英文关键词,便于搜索。

## 5. 质量红线

- 原创:禁止搬运、抄袭、改写他人成品;
- 不蹭:不收录与仓库定位无关的技能;
- 不水:禁止"一句话提示词"式敷衍技能;
- 可验证:没有验证说明的技能不得合并。
